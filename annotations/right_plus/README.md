## 以后有需要裁剪的新数据时如何填写 episodes.csv（当前 106 段无需执行）

episodes.csv 每行是一段完整示教。可用 VS Code 文本编辑器或能正确显示 UTF-8 的表格软件打开。
除非发现实际记录有误，不需要重复填写已标好的 task_id、outcome、outcome_source。

需要复核的列：
- start_video_s：播放器显示的有效任务开始秒数。
- end_video_s：播放器显示的有效任务结束秒数。
- boundary_review_status：复核完填写 reviewed，未完成保留 pending。
- include_in_training：这段适合训练填写 yes；有问题暂时填写 no 并写 notes。
- notes：写明人工摆放、长时间等待、视频截断、疑似时间不同步等情况。

操作顺序：
1. 根据 head_video_relpath 打开该行对应的头部 MP4。
2. 从开头看：物体摆好、右臂在初始姿态、任务即将开始。
3. 从结尾看：小方块已经放好且松手，右臂已经归位，堆叠保持稳定。
   若头部画面看不清右臂是否归位，在 notes 中记录，之后结合右臂关节反馈核对；不要仅凭方块堆好确定结束。
4. 保留完整堆叠和归位过程，裁掉与任务无关的准备及完成后的人工重新摆放。
5. 填写起止秒数、reviewed、yes 或 no，然后保存 CSV。

例子（只展示填写方式，不是任何一段视频的真实标注）：
若总长 40 秒，0～3 秒是准备，3～35 秒是任务及归位，35～37 秒可观察稳定，
之后开始人工重新摆放，可填 start_video_s=3、end_video_s=37、
boundary_review_status=reviewed、include_in_training=yes。
若整段内容都有效，可填开始 0、结束为视频真实播放时长，并填写 reviewed、yes。
当前 106 段已依据用户确认使用 0 和全长；以后新增未确认的数据才需要逐段决定边界。

播放器时间是 MP4 播放时间。后续转换要用 frame_index 对应到 CSV 时间戳；
不能把播放器秒数直接当成 ROS 消息的相对秒数。
